# Contributing to apim-claude-template

---

## Checklist: creating a new `api-cp-*` or `service-cp-*` repo

Complete these steps **before other team members start working on the repo*`CLAUDE.md` must exist in the new repo before anyone can run `/wire-claude-context`.

### Step 1 — Clone the new repo as a sibling

All repos must sit in the same parent directory as `apim-claude-template`:

```
~/HMCTS/APIM/
├── apim-claude-template/
├── api-cp-<new-name>/        ← new repo here
└── ...
```

```bash
cd ~/HMCTS/APIM
git clone git@github.com:hmcts/api-cp-<new-name>.git
```

### Step 2 — Wire Claude context and generate CLAUDE.md

Open the new repo in Claude Code and run:

```bash
cd api-cp-<new-name>
/wire-claude-context   # creates gitignored .claude/CLAUDE.md with 3 @import lines
/init                  # reads shared templates from context, generates + commits CLAUDE.md
```

`/init` reads real source files (OpenAPI spec, `build.gradle`, test classes, CI workflows)
and writes `CLAUDE.md` into **this repo's root**.

> If the repo has no OpenAPI spec yet (skeleton only), run `/init` again once the spec
> is added — it overwrites safely.

### Step 3 — Raise a PR on this repo for CLAUDE.md

```bash
git checkout -b dev/add-claude-context
git push -u origin dev/add-claude-context
gh pr create \
  --title "docs(claude): generate repo context" \
  --body "Auto-generated by /init. Review for accuracy before merging."
```

Get the PR reviewed and merged before telling the team the repo is ready to work on.

### Step 4 — Set up your local Claude context

```bash
/wire-claude-context
```

This writes `.claude/CLAUDE.md` (gitignored, 3 `@import` lines) pointing at shared
templates in `apim-claude-template`. Claude Code loads both this file and the committed
`CLAUDE.md` on every session — no further action needed.

### Step 5 — Tell the team

Share the repo link. Each developer runs `/wire-claude-context` once in the repo on
their own machine — that's all they need to do.

## Checklist: existing repo, architecture has changed

Run this whenever endpoints, environment variables, infrastructure, or source structure
change significantly.

```bash
cd <repo-name>
/init
```

This overwrites `CLAUDE.md` in the current repo and commits it. Raise a PR on **this repo**
(not apim-claude-template) — the CLAUDE.md change belongs in the same PR as the code change.

## Checklist: updating shared templates

For changes that apply across all repos (code rules, API patterns, service patterns):

```bash
cd apim-claude-template
git checkout -b dev/<description>

# Edit the relevant file:
# - All repos:         templates/shared-code-rules.md
# - All api-cp-*:     templates/api-spec-shared.md
# - All service-cp-*: templates/service-shared.md
# - Review policies:  skills/openapi-spec-reviewer/knowledge/

git add templates/   # or skills/
git commit -m "feat: ..."
git push -u origin dev/<description>
gh pr create --base master --title "..."
```

One merged PR here delivers the change to all repos on their next Claude Code session.

## Checklist: adding or modifying a skill

```bash
cd apim-claude-template
git checkout -b dev/<skill-name>-<change>

# Edit or create:
# - skills/<skill-name>/SKILL.md          ← skill logic
# - skills/<skill-name>/knowledge/*.md    ← policy knowledge files (if applicable)
# - .claude-plugin/marketplace.json       ← register new skills here
# - .claude/settings.json                 ← enable the new skill here

git add skills/ .claude-plugin/ .claude/settings.json
git commit -m "feat: ..."
git push -u origin dev/<skill-name>-<change>
gh pr create --base master --title "..."
```

## Where does each change go?

| Change | Repo to raise PR on |
|---|---|
| Team-wide code rule | `apim-claude-template` |
| API spec shared pattern | `apim-claude-template` |
| Service shared pattern | `apim-claude-template` |
| OpenAPI review policy | `apim-claude-template` |
| Skill logic or knowledge | `apim-claude-template` |
| One repo's architecture / endpoints / env vars | **That repo** — update `CLAUDE.md` in same PR as code |

---

## Branch naming

| Change type | Branch pattern |
|---|---|
| New repo Claude context | `dev/add-claude-context` (in the new repo) |
| Regen existing context | `dev/update-claude-context` (in that repo) |
| Shared template update | `dev/update-<template-name>` (in apim-claude-template) |
| New or changed skill | `dev/<skill-name>-<change>` (in apim-claude-template) |
| Bug fix | `fix/<description>` |

---

## PR requirements

- Target branch: `master` (apim-claude-template) or `main` (individual repos)
- At least 1 approval required (branch protection enforced)
- Title must follow `feat:` / `fix:` / `docs:` / `chore:` convention
- For `CLAUDE.md` changes in individual repos: note whether the OpenAPI spec was
  complete at generation time, or whether a re-run will be needed once the spec is added
